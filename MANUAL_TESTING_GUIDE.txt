Every protected endpoint requires the standard HTTP Authorization header:
  Authorization: Bearer <JWT_TOKEN>
  Content-Type: application/json
  X-Correlation-ID: <ANY_UUID_OR_STRING> (Optional, for distributed tracing)

5. NEGATIVE, VALIDATION & SECURITY TEST SCENARIOS
===============================================================================

Test each of the following failure scenarios to verify error handling:

Test N1: Invalid Login Credentials
  - Call: POST /api/auth/login with {"usernameOrEmail": "admin", "password": "WrongPassword"}
  - Expected: 401 UNAUTHORIZED -> {"status": 401, "error": "UNAUTHORIZED", "message": "Invalid username/email or password"}

Test N2: Account Lockout after 5 Failed Attempts
  - Call: POST /api/auth/login 5 consecutive times with bad password for "guest"
  - Expected: 403 FORBIDDEN / 423 LOCKED -> "Account has been locked due to 5 consecutive failed login attempts."
  - Verification: Check auth_db `users` table: `locked = 1`. Check notification_db: `AccountLocked` alert logged.

Test N3: Object Ownership Violation (Guest accessing another Guest's data)
  - Call: GET /api/reservations/999 with Guest 1 token when reservation belongs to Guest 2
  - Expected: 403 FORBIDDEN -> "Access denied"

Test N4: Unauthorized Role Access (Guest attempting to create Room Category)
  - Call: POST /api/room-categories with GUEST_TOKEN
  - Expected: 403 FORBIDDEN

Test N5: Double Booking Prevention
  - Call: POST /api/reservations for Room 1 with overlapping dates ("2026-11-10" to "2026-11-12") while already booked
  - Expected: 409 CONFLICT or 400 BAD REQUEST -> "Room is not available for the requested dates"

Test N6: Invalid Room State Transition (Housekeeper trying to mark CLEAN -> AVAILABLE)
  - Call: PUT /api/rooms/1/status with HOUSEKEEPER_TOKEN and {"status": "AVAILABLE"}
  - Expected: 403 FORBIDDEN -> "Housekeepers cannot directly mark rooms as AVAILABLE. Room verification required by Manager or Front Desk."

Test N7: Finalized Bill Modification Prevention
  - Call: POST /api/bills/1/items on a finalized bill
  - Expected: 400 BAD REQUEST -> "Cannot add items to finalized bill"

Test N8: Excessive Refund Rejection
  - Call: POST /api/payments/1/refund with amount 5000.00 on a $200 payment
  - Expected: 400 BAD REQUEST -> "Refund amount exceeds remaining refundable balance"

Test N9: Expired / Missing JWT Token
  - Call: GET /api/rooms with missing or malformed Authorization header
  - Expected: 401 UNAUTHORIZED
